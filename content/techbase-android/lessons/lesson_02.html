Phase 2 of 10
Prerequisite Concepts

1. What is an SDK?

An SDK (Software Development Kit) is a bundle of tools, libraries and documentation for building software on a platform. The Android SDK contains the Android framework libraries for each Android version (called SDK Platforms), plus tools such as adb, the emulator and the build tools.

2. What is Gradle? (a one-minute preview)

Gradle is the build system that turns your code into an app. Android Studio downloads it for you the first time you open a project. You will study it in lesson 03. For today, just know that your first project may spend several minutes downloading things; that is normal.

3. What is a JDK?

Android Studio is written in Java and Kotlin, so it needs a JDK (Java Development Kit) to run. Good news: Android Studio ships with its own JDK (JetBrains Runtime) so you normally do not install Java yourself. We will see where it lives in lesson 03.

4. Administrator rights

On Windows you may need administrator permission to install. On a school or work computer, ask the owner first. On Linux, you extract files into a folder you choose, and need sudo only for optional system libraries.

Phase 3 of 10
Conceptual Understanding: What You Are Installing

Installing Android Studio is really installing three layers that work together:

text
+--------------------------------------------------+
| 1. Android Studio (the IDE)                      |
|    editor, Layout tools, Logcat, debugger        |
+--------------------------------------------------+
| 2. Android SDK (in its own folder)               |
|    Platforms, Build-Tools, Platform-Tools (adb),  |
|    Emulator, system images                       |
+--------------------------------------------------+
| 3. Gradle + libraries (downloaded per project)   |
|    stored in a cache in your user folder         |
+--------------------------------------------------+

Because these are separate, you can update one without reinstalling the others. Android Studio updates itself, the SDK Manager updates the SDK, and Gradle fetches what each project requests.

Release channels

Google ships Android Studio in channels. As of this writing the official download page lists the current release by a name and a version number, and the names change with each release, so we do not repeat them here.

Channel Meaning Who should use it
Stable Fully tested release. You. Always use stable for this course.
Beta / Release Candidate Almost ready; preview of next version. Developers testing upcoming features.
Canary The newest builds, updated often, can be unstable. Experienced developers who accept crashes.

System requirements: how to read them

Google publishes system requirements for each release on the Android Studio install page. The exact numbers change, so read that page for the current figures and do not rely on a blog or on this lesson for the last digit. In general the page covers:

Item What to look for A practical guide
Operating system Supported versions of Windows, macOS, Linux and ChromeOS. 64-bit only. Use a current, updated OS.
RAM A stated minimum and a recommended amount. 8 GB is workable, 16 GB or more is comfortable, especially with the emulator.
Disk space Space for the IDE, SDK and emulator images. Plan for tens of gigabytes free, on an SSD if possible.
Screen A minimum resolution. A laptop screen is fine.
Emulator CPU virtualisation support and a supported graphics driver. Needed for lesson 04. A real phone avoids this requirement.

Honest note on cost: Android Studio, Gradle, and an emulator running at the same time can use most of 8 GB. If your computer is struggling, lesson 04 and the "Performance on a modest laptop" section below will help.

Phase 4 of 10
Step-by-Step: Download and Install

Step 1: Download from the official site

  1. Open https://developer.android.com/studio in your browser.
  2. Click the download button. Read and accept the Android SDK License Agreement when asked.
  3. The page offers a package for each platform. Typical choices are:
Platform Typical file Notes
Windows (64-bit) an .exe installer (a .zip is also offered) The installer is the easiest.
macOS, Apple silicon a .dmg for ARM Choose this for M1, M2, M3 or newer Macs.
macOS, Intel a .dmg for Intel Choose this for older Intel Macs.
Linux (64-bit) a .tar.gz archive Extract it, then run a script.
ChromeOS a .deb package For Chromebooks with Linux support.

The file is more than a gigabyte, so be patient. If your connection drops, most browsers let you resume the download; otherwise start again.

Not sure which Mac you have? Click the Apple menu, choose About This Mac. If it says "Chip: Apple M-something" choose ARM. If it says "Processor: Intel" choose Intel.

Step 2 (optional but wise): Verify the download

The download page shows a SHA-256 checksum for each file. A checksum is a fingerprint: if even one byte of the file changes, the fingerprint changes. Compare yours with the page.

bash
# macOS or Linux: print the SHA-256 of the downloaded file
shasum -a 256 ~/Downloads/android-studio-*.dmg      # macOS
sha256sum ~/Downloads/android-studio-*.tar.gz       # Linux
text
# Windows PowerShell
Get-FileHash -Algorithm SHA256 "$HOME\Downloads\android-studio-*.exe"

If the long string of letters and digits matches the page, the file is exactly what Google published. If not, download again.

Step 3: Install on your operating system

Windows

  1. Double-click the .exe file. If Windows asks whether to allow changes, choose Yes.
  2. In the setup wizard, keep the default components (Android Studio, and the Android Virtual Device option if offered).
  3. Accept the default install folder unless your C drive is nearly full. A path without spaces and special characters is safest.
  4. Finish, and tick Start Android Studio.

If you downloaded the .zip instead, extract it to a folder such as C:\Android\android-studio, and run bin\studio64.exe.

macOS

  1. Open the .dmg.
  2. Drag the Android Studio icon onto the Applications folder shortcut.
  3. Open it from Applications. If macOS warns that it was downloaded from the internet, choose Open.

Linux

Android Studio on Linux is installed by extracting an archive. Some 64-bit distributions need a few extra system libraries, and the official install page lists exactly which, so check it for your distribution.

bash
# Extract to /opt (needs sudo) or to any folder you own
sudo tar -xzf ~/Downloads/android-studio-*.tar.gz -C /opt

# Start it
/opt/android-studio/bin/studio.sh

Once it is open, you can use Tools > Create Desktop Entry (the exact wording may vary) to add a launcher to your applications menu.

Also on Linux, if you plan to use the emulator, you need KVM virtualisation support. Lesson 04 covers it in detail.

ChromeOS

The official page provides a .deb package for Chromebooks that support Linux apps. Install it from the Linux files area of your Chromebook. Emulator support depends on the hardware, so a real phone (lesson 05) may be your best route.

Step 4: The Setup Wizard

The first time Android Studio starts, a wizard appears. Screens differ a little between versions, but the choices are the same:

Wizard screen What to choose
Import settings Choose Do not import settings on a fresh install.
Data sharing Your choice. Sharing usage statistics is optional.
Install type Choose Standard. It installs the recommended SDK, tools and emulator components. Choose Custom only if you want to pick an SDK folder or theme yourself.
UI theme Light or Dark. Dark is easier on the eyes, and also on some laptop batteries.
Verify settings Shows what will download and the disk space needed.
License agreements Accept each licence. The Finish button stays disabled until you do.

After you click Finish, Android Studio downloads the SDK components. This is the largest download; leave it running. When it finishes you reach the Welcome screen with options such as New Project, Open and More Actions.

What if the wizard fails? Check your internet connection and free disk space. Then close and reopen Android Studio; the wizard can resume. If a proxy or firewall blocks it, look under Settings (search "HTTP Proxy") for proxy options. Many failures in schools are simply blocked downloads.

Step 5: Update Android Studio

Android Studio checks for updates itself and shows a notification in the bottom corner or on the Welcome screen. On Windows and Linux look under Help > Check for Updates; on macOS under Android Studio > Check for Updates (menu labels move between versions, so use Search Everywhere if you cannot find them). Updates are large too, so do them on a good connection.

Phase 5 of 10
The SDK Manager

The SDK Manager is where you install and update the Android SDK. Open it from the Welcome screen (More Actions > SDK Manager) or from an open project with Tools > SDK Manager. You can also use Search Everywhere (press Shift twice) and type "SDK Manager".

It has a few tabs. The names can differ slightly, but the idea is constant.

Android SDK Location

At the top you will see the SDK path. Typical defaults are:

OS Typical default location
Windows C:\Users\YourName\AppData\Local\Android\Sdk
macOS ~/Library/Android/sdk
Linux ~/Android/Sdk

Note this path; tools like adb live inside it, and some terminals need it later.

SDK Platforms tab

Each row is an Android version (an API level), such as "Android 15 (API 35)". Ticking a row downloads that version's framework libraries. You need the platform your project compiles against (compileSdk) plus the one for any emulator you create. You do not need every version. Each can be a few hundred megabytes with system images, so install what you need.

SDK Tools tab

This tab lists the tools. The important ones:

Tool What it does
Android SDK Build-Tools Packages and signs your apps.
Android SDK Platform-Tools Contains adb, used in lesson 05.
Android Emulator Runs virtual phones (lesson 04).
Android Emulator hypervisor driver (Windows, some setups) A virtualisation driver. Google is phasing it out in favour of the Windows Hypervisor Platform, as lesson 04 explains.
Command-line Tools sdkmanager, avdmanager and other tools for the terminal.
Google Play services and Google USB Driver Extras used by some devices and Windows USB debugging.

Tick a tool and press Apply (then OK) to install or update. Untick and apply to uninstall. Then look at the Show Package Details box at the bottom of the SDK Platforms tab; it reveals the individual packages, such as system images.

You can do the same from a terminal if the command-line tools are installed:

bash
# List installed and available packages (use the path to your SDK)
sdkmanager --list

# Install the latest platform-tools
sdkmanager "platform-tools"

On some setups you need --sdk_root=PATH_TO_SDK. Keep this for later; the graphical SDK Manager is all you need today.

How much space does it use?

text
Android Studio itself ........ about 1.5 to 3 GB
Android SDK basics ........... a few GB
Each emulator system image ... roughly 1 to 2 GB or more
Gradle cache (~/.gradle) ..... grows with every project, several GB

These are rough orders of magnitude; your numbers will differ. Delete system images you no longer use in the SDK Manager if your disk fills.

An IDE Tour

When you open a project you see something like this:

text
+-----------------------------------------------------------------------+
| File Edit View Navigate Code Refactor Build Run Tools Git Window Help |  Menu bar
+-----------------------------------------------------------------------+
| project name  | branch |   [device menu v] [> Run] [bug Debug] ...    |  Toolbar
+-----+----------------------------------------------+------------------+
| ... | Tabs of open files                            |                  |
| P   +----------------------------------------------+  Right-side      |
| r   |                                              |  tool windows    |
| o   |   EDITOR                                     |  (Device Manager,|
| j   |   (where you type code)                      |  Gradle, ...)    |
| e   |                                              |                  |
| c   |                                              |                  |
| t   |                                              |                  |
+-----+----------------------------------------------+------------------+
| Logcat | Build | Run | Terminal | Problems | ...      (bottom tools)   |
+-----------------------------------------------------------------------+
| Status bar: cursor line:column, encoding, memory, background tasks    |
+-----------------------------------------------------------------------+

The main parts

Part Purpose
Menu bar Every command, grouped. On macOS it sits at the top of the screen.
Toolbar Quick access to the run configuration, the target device, Run, Debug, and Sync.
Project tool window Your files. Use the dropdown at its top to switch between the Android view (a simplified view) and the Project view (the real folders on disk). Lesson 03 explains both.
Editor Where you read and write code. Tabs show open files.
Tool windows Panels on the edges: Logcat, Build, Run, Terminal, Problems, Device Manager, and more. Click the buttons on the edges to show and hide them.
Status bar Shows line and column, background tasks (such as Gradle sync) and sometimes memory use.
Navigation bar A clickable path of the current file.

Settings

Open Settings with Ctrl + Alt + S on Windows and Linux, and Cmd + , on macOS. On macOS the menu is under Android Studio > Settings (older versions say Preferences). Useful places:

  • Appearance & Behavior > Appearance: theme and font size of menus.
  • Editor > Font: code font and size. A larger font saves your eyes.
  • Editor > Color Scheme: syntax colours.
  • Editor > General > Auto Import: add imports automatically as you type.
  • Build, Execution, Deployment > Gradle: the Gradle JDK and offline mode.

Section names move from release to release. If you cannot find a setting, use the search box at the top of the Settings window.

Shortcuts worth learning today

Action Windows / Linux macOS
Search Everywhere (files, actions, settings) Shift Shift (twice) Shift Shift
Find Action Ctrl + Shift + A Cmd + Shift + A
Open a file by name Ctrl + Shift + N Cmd + Shift + O
Reformat code Ctrl + Alt + L Cmd + Option + L
Comment or uncomment lines Ctrl + / Cmd + /
Show quick fixes Alt + Enter Option + Enter
Basic code completion Ctrl + Space Ctrl + Space
Run the app Shift + F10 Ctrl + R
Delete the current line Ctrl + Y Cmd + Backspace
Settings Ctrl + Alt + S Cmd + ,

These are the default keymap in many versions; if one does not work, look it up with Find Action or in Settings > Keymap. The single most useful habit: when you forget where a command lives, press Shift twice and type its name.

Android Studio and AI help

Recent versions include Gemini in Android Studio, an assistant that can explain code and suggest fixes. Its availability depends on your account and version. It can be helpful, but treat suggestions as hints to be understood, not copied blindly. You are here to learn.

Phase 7 of 10
Performance on a Modest Laptop

If you have 8 GB of RAM, a few settings make life far smoother.

  1. Close other heavy programs (browsers with many tabs, games) while Studio is open.
  2. Memory settings: Use Help > Change Memory Settings (name may vary) to see the IDE heap size. Do not give the IDE more than your computer can spare. The default is usually a sensible choice.
  3. Gradle memory: The file gradle.properties in a project controls Gradle's memory. A line such as the one below is common, and you can lower it on a small machine (the number is in the project's template):
text
org.gradle.jvmargs=-Xmx2048m -Dfile.encoding=UTF-8
  1. Power Save Mode: The File menu has a Power Save Mode item that turns off background code analysis. It saves memory and battery but disables helpful hints, so use it only when needed.
  2. Use a real phone instead of an emulator (lesson 05).
  3. Keep the SDK on an SSD, and make sure there is free space.

Troubleshooting installation

Problem Likely cause What to do
Download keeps stopping Weak network Use a download manager or try off-peak.
"Windows protected your PC" Normal for a new installer Choose More info > Run anyway, only if downloaded from the official site.
Wizard cannot download SDK Proxy, firewall or low space Check connection, disk space, proxy settings.
Studio will not start on Linux Missing libraries or JDK problem Read the install page's library list for your distribution.
Very slow editor Not enough RAM Close apps, lower memory settings, use Power Save Mode.

🎯 Your Challenge

Exercise 1: Fill in your installation card

After installing, collect these facts about your own installation and write them down:

  1. Your Android Studio version (find it in Help > About or Android Studio > About Android Studio).
  2. Your SDK location (from the SDK Manager).
  3. Which SDK Platform versions are installed (tick marks in the SDK Platforms tab).
  4. Whether Android SDK Platform-Tools and Android Emulator appear as installed in the SDK Tools tab.
  5. Three shortcuts you have tried, and what each did.

There is no single right answer, because it depends on your machine. A good answer looks like this:

text
Android Studio: (name and version from the About dialog)
SDK location:   C:\Users\Tunde\AppData\Local\Android\Sdk
Platforms:      one recent Android platform installed
Tools:          Build-Tools, Platform-Tools and Emulator installed
Shortcuts:      Shift Shift (searched "Logcat"), Ctrl+Alt+L (reformat),
                Ctrl+/ (comment)

If Platform-Tools or Emulator is missing, tick it in the SDK Tools tab, click Apply, and let it download.

Exercise 2: Find it with Search Everywhere

Without using the menu bar, use only Shift Shift to (a) open the SDK Manager, (b) find the setting that controls the editor font size, (c) open the Device Manager.

  1. Press Shift twice, type SDK Manager, press Enter.
  2. Press Shift twice, type Font, and pick Editor > Font under the Settings results (the wording depends on your version).

Search Everywhere searches files, actions and settings, so you never need to memorise a menu path.

🎯 Your Challenge

Exercise 3: Verify a download

Using the commands from this lesson, work out whether a download is genuine.

  1. You downloaded the Linux archive. Which command prints its SHA-256?
  2. The printed value is 3f2a...9c1d, but the page shows 3f2a...9c1e. What do you do?
  1. sha256sum ~/Downloads/android-studio-*.tar.gz
  2. Do not install it. Even one different character means the file is not identical to the published one, often because the download was cut off or corrupted. Delete it and download again from the official site, then compare again.

Phase 9 of 10
Common Beginner Mistakes (and How to Fix Them)

Mistake #1: Downloading from an unofficial site. The problem: "free download" sites may bundle malware or ancient versions. The fix: only use developer.android.com/studio.

Mistake #2: Choosing the wrong Mac package. The problem: the Intel build on Apple silicon (or the reverse) can run slowly or not at all. The fix: check About This Mac first.

Mistake #3: Installing into a folder with spaces or special characters. The problem: some tools in the chain behave badly with unusual paths. The fix: use simple paths such as C:\Android for the zip install, and avoid non-English characters in your user folder name where possible.

Mistake #4: Cancelling the wizard's downloads halfway. The problem: later projects fail with "SDK not found" or missing platform messages. The fix: reopen Studio, and finish the setup or use the SDK Manager to install the missing parts.

Mistake #5: Installing every SDK Platform. The problem: it fills your disk with gigabytes you will never use. The fix: install the latest stable platform plus any older one you intentionally test on.

Mistake #6: Running the emulator without virtualisation turned on. The problem: the emulator refuses to start or is painfully slow. The fix: enable VT-x or SVM in your BIOS (lesson 04).

Mistake #7: Using Canary builds to learn. The problem: they can crash or break your project. The fix: stay on Stable.

Mistake #8: Ignoring the Gradle sync message. The problem: the first project seems stuck. The fix: look at the status bar or the Build window. Large downloads on a slow line can take a long time, and the progress is shown there.

Phase 10 of 10
Knowledge Check

Question 1. Why does Android Studio not need you to install Java separately?

Android Studio ships with its own bundled JDK (a JetBrains Runtime build), so it can run and build projects without a separate Java installation.

Question 2. What is the difference between the SDK Platforms tab and the SDK Tools tab?

SDK Platforms holds the Android framework libraries for each Android version (API level) that you compile and test against. SDK Tools holds tools such as Build-Tools, Platform-Tools (adb), the Emulator and the command-line tools.

Question 3. What does a SHA-256 checksum let you check?

Whether the file you downloaded is byte-for-byte identical to the one the publisher released. A different checksum means a corrupted or altered file.

Question 4. Which shortcut helps you find any menu command, file or setting?

Search Everywhere: press Shift twice. (Find Action, Ctrl + Shift + A or Cmd + Shift + A, searches only commands.)

Question 5. Which release channel should you use for this course, and why?

Stable. It is fully tested. Canary and preview channels can be unstable and can break your projects while you are learning.

🐙 Push to GitHub  ▼
1

Open your finished project in Android Studio. Check that the .gitignore file the wizard created is in the project root. It keeps local.properties, build folders and keystores out of Git. Never commit passwords or signing keys.

2

Choose Git > Create Git Repository… (or VCS > Enable Version Control Integration in older versions), select the project folder, then open Git > Commit, tick every file, and write the message “Add Android lesson 02 project”.

3

On github.com click New repository, name it android-lesson-02-download-and-install-android-studio, set it to Public, leave Add a README unticked, and click Create repository.

4

Back in Android Studio choose Git > Manage Remotes…, add the repository URL as origin, then choose Git > Push… and push your main branch. Prefer the terminal? Run git remote add origin <your-url> then git push -u origin main.

5

Add a README.md with a screenshot of your app running and a short description. Employers and clients read READMEs first. Your project is now part of your public portfolio. 🎉
