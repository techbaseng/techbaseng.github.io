Lesson Introduction

Welcome to the most exciting phase of the course! You have set up Android Studio (lessons 01 to 05) and learned the Kotlin you need (lessons 06 to 14). Now you finally start building screens. Today you meet Jetpack Compose, the modern toolkit that Google recommends for building Android user interfaces, and you use it to make a real, good-looking birthday card app.

Picture a sign-writer in the market painting a shop board. Old-style Android was like giving the sign-writer a long instruction sheet written in a separate language (XML) and then telling a second person (Kotlin) to go and change the paint later. Compose is like the sign-writer simply describing the board in one language: "a big bold greeting, and under it, a smaller name, to the right." If the greeting changes, you describe the board again and Compose repaints what needs repainting.

By the end of this lesson you will be able to:

  • Explain what Jetpack Compose is and what "declarative UI" means.
  • Read the code of a freshly generated Compose project: MainActivity, setContent, the theme and Surface.
  • Write your own composable functions and follow the rules for them.
  • Show and style text with Text, fontSize, fontWeight, color, textAlign and lineHeight.
  • Explain the difference between sp and dp.
  • Preview your UI without running the app, using @Preview.
  • Arrange several composables with Column and Box, and give them space with Modifier.
  • Move text into strings.xml and show it with stringResource.
  • Build the Birthday Card app and a second Compose Article app.

How this fits the bigger picture: This lesson covers three items from Unit 1, Pathway 3 of Google's Android Basics with Compose course: Intro to Jetpack Compose, Design a birthday card app and Build a simple app with text composables (the "Compose Article" practice app). We follow the same ideas with our own code and designs. Links to the official pages are at the end.

Costs and requirements

Compose previews and the emulator both use memory. If your laptop has 8 GB of RAM, close your browser tabs before running the emulator, or use a real phone as you learned in lesson 05. Previews (this lesson's star feature) are lighter than the emulator, so you can do a lot of your work without launching it.

Phase 3 of 12
Conceptual Understanding: Declarative UI and Composable Functions

What is Jetpack Compose?

Jetpack Compose is Android's modern UI toolkit. You write your user interface entirely in Kotlin, by calling functions that each describe a piece of the screen. It is part of Jetpack, Google's family of Android libraries that you add to a project as dependencies.

Declarative versus imperative

Style You write Analogy
Imperative (old Views) Step-by-step commands: find the label, set its text, change its colour Directing a painter stroke by stroke
Declarative (Compose) A description of what the screen should look like for the current data Handing the painter a photo of the finished picture

In Compose you do not reach into the screen and tweak it. You write a function that says "given this name, show this greeting." When the data changes, Compose calls your function again and updates the screen. Lesson 17 and 19 show how data changes trigger that, using state.

A composable function

A composable function is an ordinary Kotlin function with the @Composable annotation. It does not return the UI. It emits UI into the tree that Compose is building.

kotlin
import androidx.compose.material3.Text
import androidx.compose.runtime.Composable

@Composable
fun Greeting(name: String) {
    Text(text = "Hello, $name!")
}

The rules to remember:

Rule Why
Add @Composable above fun. It tells the Compose compiler this function describes UI.
Composables can only be called from other composables (or from setContent). Compose needs to be tracking the call.
Name them with a noun in PascalCase: Greeting, BirthdayCard. It is the Compose style guide's convention, and it makes them look like UI elements. Normal functions use camelCase verbs.
Accept a modifier: Modifier = Modifier parameter. It lets the caller control size and position. You will see this pattern everywhere.
Do not rely on a return value. A composable normally returns nothing (Unit).

The UI tree

Composables call other composables, so your screen is a tree:

text
setContent
   └── BirthdayCardTheme          (colours, fonts)
         └── Surface              (a background)
               └── BirthdayGreeting
                     ├── Text("Happy Birthday Ada!")
                     └── Text("From Tunde")

Each branch is a function call. The leaves are the things the user actually sees, such as Text.

Why composables are cheap to repeat

Because the UI is only a description, calling a composable many times costs little. You can make a Greeting for ten names with a loop. Compose also skips work: when data has not changed it does not redraw that part. This is called recomposition and lesson 19 explains it properly.

MainActivity.kt
package com.techbase.birthdaycard

import android.os.Bundle
import androidx.activity.ComponentActivity
import androidx.activity.compose.setContent
import androidx.activity.enableEdgeToEdge
import androidx.compose.material3.Text
import androidx.compose.runtime.Composable
import androidx.compose.ui.Modifier
import androidx.compose.ui.tooling.preview.Preview
import com.techbase.birthdaycard.ui.theme.BirthdayCardTheme

class MainActivity : ComponentActivity() {
    override fun onCreate(savedInstanceState: Bundle?) {
        super.onCreate(savedInstanceState)
        enableEdgeToEdge()
        setContent {
            BirthdayCardTheme {
                Greeting(name = "Android")
            }
        }
    }
}

@Composable
fun Greeting(name: String, modifier: Modifier = Modifier) {
    Text(
        text = "Hello $name!",
        modifier = modifier
    )
}

@Preview(showBackground = true)
@Composable
fun GreetingPreview() {
    BirthdayCardTheme {
        Greeting("Android")
    }
}

Block by block:

Piece Meaning
class MainActivity : ComponentActivity() An Activity is one screen-sized window of your app. ComponentActivity is the base class that supports Compose. Lesson 23 explains the Activity lifecycle.
onCreate(...) Android calls this when the screen is created. Our setup goes here.
super.onCreate(savedInstanceState) Lets the parent class do its own set-up first. Always keep it.
enableEdgeToEdge() Lets the app draw behind the status bar and navigation bar, which is the modern Android look. Because of this you must sometimes add padding so your content is not hidden underneath them. We handle that below.
setContent { ... } The bridge from Android to Compose. Everything inside the braces is composable.
BirthdayCardTheme { ... } Applies the app's colours, typography and shapes to everything inside (lesson 22 covers theming).
@Preview Marks a function that Android Studio should render in its Design pane. It is only for development; it does not ship in the app's behaviour.

Run the app (the green triangle). You should see "Hello Android!" in the top-left corner of the screen. Congratulations: that is a Compose app.

Step 4: Meet the Preview pane

At the top right of the code editor are three buttons: Code, Split and Design. Choose Split. If the preview says it is out of date, click Build & Refresh (or the refresh icon). You should see the text "Hello Android!" on a white card inside the preview, without starting an emulator.

Edit the text in Greeting and look at the preview: after a short build it updates. Previews are the fastest feedback loop you have, so use them constantly.

A few preview rules:

  • A @Preview function must be @Composable and must take no parameters (unless you use a special advanced feature covered in lesson 44).
  • showBackground = true paints a background so white text would not vanish.
  • You can have several previews in a file to see different states.
  • If the preview shows an error, read the message in the pane; it is usually a missing import or a build error elsewhere.

Step-by-Step: Making Text Look the Way You Want

Text is the composable that shows words. The version to use is androidx.compose.material3.Text. You can pass only the text or add many styling parameters.

The most useful Text parameters

Parameter Example Effect
text "Hello" The words to show.
fontSize 32.sp Size of the letters.
fontWeight FontWeight.Bold Thickness: Light, Normal, Medium, SemiBold, Bold.
fontStyle FontStyle.Italic Slanted text.
fontFamily FontFamily.Serif, Cursive, Monospace A built-in family of letter shapes.
color Color(0xFF3E2723) Text colour.
textAlign TextAlign.Center Alignment inside the width the Text has.
lineHeight 36.sp Distance between lines.
letterSpacing 2.sp Extra gap between letters.
maxLines and overflow 2, TextOverflow.Ellipsis Cut long text with "..."
style MaterialTheme.typography.headlineMedium A bundle of settings from the theme.

sp versus dp

Compose measures space with two units, and mixing them up is the number one beginner slip.

Unit Stands for Used for Scales with the user's font-size setting?
dp density-independent pixels Sizes of things: padding, widths, heights No
sp scale-independent pixels Text size only Yes

A phone can have a tiny screen with a crowded display or a large one. A dp is built so that 16.dp looks about the same physical size on both. An sp is the same, but it also multiplies by the person's font size preference in the phone's Settings. A learner who struggles to read small text raises that setting; if you used dp for text, you would ignore their choice. That is why text always uses sp (lesson 47 returns to this under accessibility).

Both units need an import and the dot-suffix on a number:

kotlin
import androidx.compose.ui.unit.dp
import androidx.compose.ui.unit.sp

Example: a styled greeting

kotlin
import androidx.compose.material3.Text
import androidx.compose.runtime.Composable
import androidx.compose.ui.graphics.Color
import androidx.compose.ui.text.font.FontFamily
import androidx.compose.ui.text.font.FontWeight
import androidx.compose.ui.text.style.TextAlign
import androidx.compose.ui.tooling.preview.Preview
import androidx.compose.ui.unit.sp

@Composable
fun StyledGreeting() {
    Text(
        text = "Happy Birthday!",
        fontSize = 40.sp,
        fontWeight = FontWeight.Bold,
        fontFamily = FontFamily.Serif,
        color = Color(0xFF6A1B9A),
        textAlign = TextAlign.Center,
        lineHeight = 48.sp
    )
}

@Preview(showBackground = true)
@Composable
fun StyledGreetingPreview() {
    StyledGreeting()
}

What you should see in the preview: the words "Happy Birthday!" in bold, serif, purple letters at the top-left of the preview.

A few things to notice:

  • Color(0xFF6A1B9A) builds a colour from a hexadecimal number. The first two digits (FF) mean fully opaque, then red, green and blue pairs (6A, 1B, 9A). Import it from androidx.compose.ui.graphics.Color.
  • textAlign = TextAlign.Center has no visible effect on a single short line, because the Text is only as wide as its words. Alignment works inside the width the Text has. Give the Text more width (for example Modifier.fillMaxWidth()) and the centring becomes visible. This puzzles almost everyone the first time.
  • When two lines of large text wrap, lineHeight keeps them from touching or drifting apart. A good rule of thumb is a line height of roughly 1.1 to 1.3 times the font size for headings.

 +-------+                             B sits over A

Modifier: how you decorate and size a composable

A Modifier is a chain of instructions that changes how a composable looks or behaves: its size, padding, background, click behaviour and more. You build it by chaining calls with dots, and order matters.

kotlin
Modifier
    .fillMaxWidth()      // take all the available width
    .padding(16.dp)      // then add 16dp of space around the content

Common modifiers:

Modifier Effect
fillMaxSize(), fillMaxWidth(), fillMaxHeight() Fill the space the parent offers.
padding(16.dp) Space inside the edge of this element (between its border and its content).
size(48.dp), width(...), height(...) Exact sizes.
background(Color) Paint a background colour.
safeDrawingPadding() Add padding so content avoids the status bar, navigation bar and cut-outs. We use it because of enableEdgeToEdge().

A neat trick to remember the order rule: Modifier.padding(16.dp).background(Color.Red) puts the padding outside the red area (the red box is smaller). Modifier.background(Color.Red).padding(16.dp) paints the red first, then pads the content inside it. Try both in a preview to see it.

Alignment and Arrangement (preview)

Column has two parameters that place its children: verticalArrangement (how children are spaced along the column, up and down) and horizontalAlignment (where they sit across the column, left to right). For now remember that Arrangement.Center centres the group vertically and Alignment.CenterHorizontally centres it sideways. Lesson 16 explores this in depth.

Step-by-Step: Strings in `strings.xml`

We have been typing words directly into code. That works but has two problems: you cannot translate the app easily, and the same wording ends up copied in many places. Android keeps visible text in a resource file instead.

  1. Open app > res > values > strings.xml.
  2. Add your strings:
strings.xml
<resources>
    <string name="app_name">Birthday Card</string>
    <string name="happy_birthday_text">Happy Birthday %1$s!</string>
    <string name="signature_text">From %1$s</string>
</resources>

%1$s is a placeholder: "the first argument, as a string". A translator can move it wherever their language needs. For example, a Yoruba or French version might put the name in a different spot in the sentence.

  1. Use them in Compose with stringResource:
kotlin
import androidx.compose.ui.res.stringResource

// inside a composable:
val message = stringResource(R.string.happy_birthday_text, "Ada")
val signature = stringResource(R.string.signature_text, "Tunde")

R is a class Android generates that holds an id for every resource. R.string.happy_birthday_text is that string's id. stringResource can only be called from a composable.

Tip: If R shows as red, you probably need to build the project (Build > Make Project) so Android generates it, or the file is in a different package from your namespace. If so, add import com.techbase.birthdaycard.R.

Step-by-Step Build: The Birthday Card App

Time to put it all together. We build in three small stages and look at the result of each.

Stage 1: The greeting composable

Create BirthdayGreeting: two texts in a column. Replace the contents of MainActivity.kt below the imports as shown in stage 3; first read the composable on its own:

kotlin
@Composable
fun BirthdayGreeting(message: String, from: String, modifier: Modifier = Modifier) {
    Column(
        verticalArrangement = Arrangement.Center,
        modifier = modifier.padding(8.dp)
    ) {
        Text(
            text = message,
            fontSize = 56.sp,
            lineHeight = 64.sp,
            fontWeight = FontWeight.Bold,
            textAlign = TextAlign.Center,
            color = Color(0xFF3E2723),
            modifier = Modifier.fillMaxWidth()
        )
        Text(
            text = from,
            fontSize = 28.sp,
            fontStyle = FontStyle.Italic,
            color = Color(0xFF3E2723),
            modifier = Modifier
                .padding(16.dp)
                .align(Alignment.End)
        )
    }
}

How it works:

  • The function takes the two texts as parameters, so the card is reusable for anyone. It does not know it is for Ada.
  • The modifier parameter has a default of Modifier, so callers may ignore it. Inside we use modifier.padding(8.dp), which means "whatever the caller asked for, plus 8dp of padding". Passing the caller's modifier to the outermost element is a convention to follow.
  • Column(verticalArrangement = Arrangement.Center) centres both texts vertically when the column is tall (it will be, because the caller passes fillMaxSize).
  • The first Text uses fillMaxWidth() so TextAlign.Center is visible.
  • The signature uses Modifier.align(Alignment.End), which only exists inside a Column, and pushes it to the right-hand side.
  • Both texts set color explicitly. See the common mistakes for why that matters.

In MainActivity, we wrap the greeting in a Surface that gives a warm background colour.

What you should see when you run it: a warm cream-coloured screen. In the vertical middle, "Happy Birthday Ada!" appears large, bold and centred, probably wrapping onto two or three lines on a phone. The preview looks almost the same, except the background is white (the cream comes from the Surface that only exists in MainActivity). That is normal: a preview shows only the composable you call in it.

Understanding Surface

Surface is a Material composable that paints a background and sets the default text colour for its children. We gave it a custom color. Because that colour is not one of the theme's colours, Compose does not know what text colour suits it, so we set color on each Text ourselves. If we had used MaterialTheme.colorScheme.background, the text would follow the light or dark theme automatically.

Exercise 2: Fix the broken composable

This code has four problems. Find them before running.

kotlin
import androidx.compose.material3.Text

fun welcomeMessage(name: String) {
    Text(
        text = "Welcome $name",
        fontSize = 24,
        color = "blue"
    )
}
  1. The function is missing @Composable. Without it, calling Text gives the error @Composable invocations can only happen from the context of a @Composable function.
  2. fontSize = 24 is an Int. Text size needs a TextUnit, so write 24.sp (and import androidx.compose.ui.unit.sp).
  3. color = "blue" is a String. Colours are Color values: Color.Blue or Color(0xFF0000FF) (import androidx.compose.ui.graphics.Color).
  4. The name welcomeMessage starts with a lowercase letter. It works, but composables that emit UI should be named in PascalCase, so rename it WelcomeMessage.
kotlin
import androidx.compose.material3.Text
import androidx.compose.runtime.Composable
import androidx.compose.ui.graphics.Color
import androidx.compose.ui.unit.sp

@Composable
fun WelcomeMessage(name: String) {
    Text(
        text = "Welcome $name",
        fontSize = 24.sp,
        color = Color.Blue
    )
}

Common Beginner Mistakes (and How to Fix Them)

Mistake #1: Forgetting @Composable. The wrong code: a plain fun Greeting() { Text("Hi") } The problem: the compiler reports that @Composable invocations can only happen from a composable context. The fix: put @Composable on the line directly above fun.

Mistake #2: Typing a size without sp or dp. The wrong code: fontSize = 24 or padding(16). The problem: the number is an Int, not a unit, so the types do not match. The fix: 24.sp for text and 16.dp for spacing, with the matching imports from androidx.compose.ui.unit.

Mistake #3: Using dp for text size. The wrong code: fontSize = 20.dp The problem: a type error, but even if you convert it, text must scale with the user's font preference. The fix: sp for text, dp for everything else.

Mistake #4: Importing the wrong Text. The symptom: parameters are not recognised, or text ignores the theme. The fix: make sure the import is androidx.compose.material3.Text. Android Studio may offer several Text classes when you press Alt + Enter; pick the Material 3 one.

Mistake #5: Centred text that does not look centred. The wrong code: Text("Hi", textAlign = TextAlign.Center) on its own. The problem: the Text is only as wide as its words, so there is nothing to centre inside. The fix: add modifier = Modifier.fillMaxWidth(), or centre the whole composable with the parent's horizontalAlignment.

Mistake #6: Dark text on a dark background. The problem: you set a custom Surface colour and then your phone's dark mode switches the default text to near-white (or the opposite), making it unreadable. The fix: either use theme colours (MaterialTheme.colorScheme.background, which come with matching content colours) or set the color of your text explicitly. Test your screen in both light and dark mode (lesson 22 covers dark theme).

Mistake #7: Content hidden under the status bar. The cause: enableEdgeToEdge() lets your app draw behind the system bars. The fix: add Modifier.safeDrawingPadding(), statusBarsPadding(), or use a Scaffold (lesson 38) and apply its innerPadding.

Mistake #8: @Preview with parameters. The wrong code: @Preview @Composable fun P(name: String) { ... } The problem: previews cannot be given arguments this way. The fix: create a no-parameter preview function that calls your composable with sample values.

Mistake #9: Hard-coding long text in composables. The problem: translations are impossible and changes happen in many places. The fix: put text in strings.xml and use stringResource(R.string.name).

Mistake #10: Putting R.string.x directly into Text. The wrong code: Text(R.string.title) The problem: R.string.title is just an Int id, not the words. The fix: Text(stringResource(R.string.title)).

Knowledge Check

Answer each question in your head (or on paper), then reveal the answer.

Question 1. What does the @Composable annotation tell Android Studio and the compiler, and where can a composable function be called from?

It marks the function as one that describes part of the UI, so the Compose compiler can track it. A composable can only be called from another composable function or from the setContent { } block of an Activity.

Question 2. What is the difference between sp and dp, and which should you use for text?

Both are density-independent units. sp also scales with the user's font-size setting, so it is used for text. dp does not, and is used for sizes and spacing such as padding, width and height.

Question 3. What does @Preview do, and why is it useful?

It tells Android Studio to render that composable in the Design or Split pane, so you see your UI immediately without installing and launching the app on an emulator or phone. It speeds up development. A preview function must be @Composable and take no parameters.

Question 4. In Modifier.padding(16.dp).background(Color.Red), is the padding inside or outside the red area? What happens if you swap the two calls?

The padding is outside the red area, because it was applied first, so the red box is smaller. If you swap them (background(...) then padding(...)) the red is painted first and the padding is applied inside it, giving a larger red area with the content inset. Modifier order matters.

Question 5. Why should the visible words of an app live in strings.xml, and how do you read one in Compose?

It keeps wording in one place, lets the app be translated into other languages, and supports placeholders like %1$s. In Compose you read it with stringResource(R.string.the_name), adding arguments for placeholders, for example stringResource(R.string.happy_birthday_text, "Ada").
