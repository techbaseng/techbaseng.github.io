Why learn Android at all?

Android runs on billions of active devices worldwide, and in Nigeria and much of Africa it is by far the most common kind of smartphone. That means an app you build can reach real people: a school register for your community, a market price tracker, a booking tool for a salon, a fee reminder for a school. You do not need a company, a licence or a big laptop to start. You need patience, a computer that can run Android Studio, and a plan. This course is the plan.

Phase 2 of 11
Prerequisite Concepts

You need very little. These are the only ideas we assume, and each is explained in a paragraph.

1. You can use a smartphone

You have used apps. You know that tapping an icon opens an app, that apps have screens, and that they sometimes ask permission to use your camera or location. That experience is your best starting point, because a developer is just someone who builds the things you already tap.

2. What is software?

Software is a set of instructions stored as files. The phone's processor follows those instructions. An app is software that a person can install and launch from the home screen. The operating system is also software; it is the program that runs all the other programs and shares the screen, battery, memory and network between them.

3. What is an operating system?

An operating system (OS) is the manager of the device. When two apps both want the screen, the camera or the battery, the OS decides who gets what. Windows, macOS, Linux, iOS and Android are all operating systems. Android is the OS in most phones, tablets, smart TVs, watches and car dashboards you will meet.

4. What is a programming language?

A programming language is a strict way of writing instructions so a machine can follow them. You will meet Kotlin properly in lessons 06 to 14. Today we only look at a few lines so that nothing feels mysterious later.

Phase 3 of 11
Conceptual Understanding: What Android Is

Android is an open-source mobile operating system led by Google. "Open source" means the core code, the Android Open Source Project (AOSP), is published so manufacturers can build on it. Samsung, Tecno, Infinix, Xiaomi, Nokia and many others take that base, add their own look and features, and ship phones. Google then adds its own apps and services (Google Play, Maps, Gmail and more) on top for devices that meet its compatibility requirements. This is why two Android phones can look different and yet run the same apps.

The layers of Android

Android is built like a tall building. Each floor depends on the floors below it and offers services to the floors above it.

text
+--------------------------------------------------+
|  YOUR APP and other apps (Kotlin + Compose)      |  <- you work here
+--------------------------------------------------+
|  Android Framework (APIs: Activity, Intent,      |
|  notifications, location, camera, storage)       |
+--------------------------------------------------+
|  Android Runtime (ART)    |  Native libraries    |
|  runs your app's code     |  (graphics, media,   |
|                           |   SQLite, WebView)   |
+--------------------------------------------------+
|  Hardware Abstraction Layer (HAL)                |
|  a common way to talk to camera, audio, sensors  |
+--------------------------------------------------+
|  Linux kernel (drivers, memory, processes,       |
|  security, power management)                     |
+--------------------------------------------------+
|  HARDWARE: CPU, screen, battery, radio, sensors  |
+--------------------------------------------------+
Layer What it does Analogy
Linux kernel Talks to the hardware, manages memory, processes, security and power. The building's foundations and electrical wiring.
Hardware Abstraction Layer Gives the layers above one standard way to use a camera or sensor, whatever company made it. A universal plug adapter.
Android Runtime and native libraries Runs your app's code and provides fast low-level services such as graphics and databases. The engine room.
Android Framework The Java and Kotlin APIs you call every day: screens, notifications, permissions, location. The lift, the water and the power sockets that residents use.
Apps What users see and tap. The shops and flats.

As an app developer you almost always work on the top two floors. You rarely touch the kernel. But knowing the lower floors exist explains many things later, for example why your app is not allowed to read another app's private files (the kernel gives each app its own sandbox).

What is ART?

You write Kotlin, but a phone's processor does not understand Kotlin. The journey looks like this:

text
Kotlin source (.kt)
      |  Kotlin compiler
      v
Java bytecode (.class)
      |  D8 / R8 tools (dexing and shrinking)
      v
DEX bytecode (classes.dex) packed into the APK / AAB
      |  installed on the phone
      v
ART (Android Runtime): compiles and runs it on the device

ART, the Android Runtime, is the part of Android that runs your compiled app on the device. It uses a mix of strategies, including compiling code ahead of time and compiling frequently used code while the app runs, so apps start quickly and run smoothly. You do not need to manage that. What matters to you: your Kotlin code is turned into a compact format called DEX, and ART is what runs it on every phone.

APK and AAB: the two packages you will meet

When you build an app, Android Studio packages everything into a file.

Format Full name Who uses it
APK Android Package The installable file. You can copy an APK to a phone and install it directly. Debug builds on your own device are APKs.
AAB Android App Bundle The format you upload to Google Play. Google Play uses it to build optimised APKs for each device.

An APK is really a ZIP archive. It contains your compiled code, your images and layouts, and the manifest that describes the app. An AAB holds the same ingredients, but it lets Google Play generate a smaller download tailored to the user's phone, for example only the screen density and CPU type that phone needs. That matters a great deal for people on limited mobile data. You will build and publish a bundle in lessons 49 to 53.

Google Play and other ways to distribute

Google Play is the main store. Developers register, upload a bundle, fill in a store listing and publish. Apps can also be shared as APK files, through company-internal distribution or through other stores, but Play is where most users look. A whole programme of this course (Google Play Store Listing Certificate) covers it.

Languages and tools

Choice What Android developers use today What this course uses
Language Kotlin (Google's preferred language), Java (still supported), C and C++ for special cases Kotlin
UI toolkit Jetpack Compose (modern, declarative), classic Views with XML (older apps) Compose first; Views in lessons 42 and 43
IDE Android Studio, built on IntelliJ IDEA Android Studio
Build system Gradle with the Android Gradle Plugin (AGP) Gradle Kotlin DSL

Google announced in 2019 that Android development would be Kotlin-first. Jetpack Compose lets you describe a screen as Kotlin functions instead of writing separate XML files, so there is less to learn and less to keep in sync.

Think about it: Why might a phone maker want an operating system it does not have to write from scratch? (It saves years of work and lets thousands of developers build apps for its phones.)

Phase 4 of 11
A First Look at Real Android Code

You will not understand every line yet, and that is perfectly fine. The goal is to see that Android code is made of ordinary, readable pieces.

Piece 1: the manifest

Every app has a file called AndroidManifest.xml. It is the app's identity card, listing screens and permissions.

xml
<?xml version="1.0" encoding="utf-8"?>
<manifest xmlns:android="http://schemas.android.com/apk/res/android">

    <application
        android:label="Hello Ibadan"
        android:icon="@mipmap/ic_launcher">

        <activity
            android:name=".MainActivity"
            android:exported="true">
            <intent-filter>
                <action android:name="android.intent.action.MAIN" />
                <category android:name="android.intent.category.LAUNCHER" />
            </intent-filter>
        </activity>

    </application>
</manifest>

Reading it aloud: "This app is labelled Hello Ibadan. It has one screen, MainActivity. That screen is the one to open when the user taps the launcher icon." The intent-filter with MAIN and LAUNCHER is what marks the starting screen. Lesson 03 explains every attribute.

Piece 2: an Activity

An Activity is one entry point into your app's UI, roughly "a window of the app".

kotlin
package com.example.helloibadan

import android.os.Bundle
import androidx.activity.ComponentActivity
import androidx.activity.compose.setContent
import androidx.compose.material3.Text

class MainActivity : ComponentActivity() {
    override fun onCreate(savedInstanceState: Bundle?) {
        super.onCreate(savedInstanceState)
        setContent {
            Text("Hello, Ibadan!")
        }
    }
}

When Android starts the screen it calls onCreate. Inside, setContent { ... } says "this is what the screen should show". Here it shows one line of text. You will study this in lesson 15 and the activity lifecycle in lesson 23.

Piece 3: a composable function

In Jetpack Compose the UI is built from small functions marked @Composable.

kotlin
import androidx.compose.material3.Text
import androidx.compose.runtime.Composable

@Composable
fun Greeting(name: String) {
    Text(text = "Hello, $name!")
}

Call Greeting("Tunde") and the screen shows Hello, Tunde!. Compare that with the older way of writing a layout in XML, an Activity and a lot of glue code. Compose is far shorter.

Piece 4: the build file

Gradle build files tell the tools how to assemble the app. This tiny extract names the app and the Android versions it supports:

kotlin
android {
    namespace = "com.example.helloibadan"
    defaultConfig {
        applicationId = "com.example.helloibadan"
        minSdk = 24
    }
}

applicationId is the app's unique name on a device and on Google Play. minSdk is the oldest Android version the app supports. Exact numbers change between Android Studio releases, and you will choose them in lesson 03.

Piece 5: what the toolchain does with those files

bash
# A typical command-line build, run in the project folder
# (macOS and Linux)
./gradlew assembleDebug

# (Windows)
gradlew.bat assembleDebug

This asks Gradle to compile everything and produce a debug APK. You will almost never type it, because Android Studio's Run button does it for you, but it is useful to know the button is not magic.

Phase 5 of 11
Android Versions, API Levels and Compatibility

Android has marketing names and numbers (Android 14, Android 15 and so on), but developers care about API levels: a whole number that identifies a version of the Android framework. Each new Android release adds an API level with new features. Three numbers appear in every project:

Setting Meaning Why you care
minSdk The oldest API level your app supports. A lower value reaches more old phones but limits the features you can use directly.
targetSdk The API level your app is tested against. Google Play requires recent targets for new apps and updates, and the required number moves over time.
compileSdk The API level of the framework you compile against. It gives you access to the newest APIs while writing code.

Jetpack: libraries that smooth out the differences

Phones in the real world run many Android versions. Jetpack is a family of libraries (called androidx) that gives you the same modern tools on old and new phones: Compose, ViewModel, Navigation, Room, WorkManager and many more. You will meet them one by one. When you see an import that starts with androidx., you are using Jetpack.

Before You Begin: Prepare Your Setup

This section matches the official Before you begin item. It is about being ready, not about downloading anything yet.

Your computer

Android Studio is a large program. Google publishes official system requirements, and they change between releases, so always read the current version on the Android Studio install page. As a rough guide, which lesson 02 explains in detail:

Resource Minimum you should expect Comfortable
RAM 8 GB 16 GB or more
Free disk space Tens of GB (Studio, SDK, emulator images, Gradle cache) An SSD with 50 GB free or more
Screen A laptop screen is enough A second monitor helps
Operating system A current 64-bit Windows, macOS or Linux Same

If your laptop is modest, do not give up. Lesson 04 covers low-RAM alternatives and lesson 05 shows how to run apps on a real phone, which uses far less of your computer than an emulator.

Your internet connection

The first installation downloads several gigabytes (Android Studio itself is over a gigabyte, plus the SDK and Gradle libraries). Plan to do the first setup on a good connection, perhaps at a hub or a friend's Wi-Fi, and keep the downloaded installer. After that, daily work uses much less data, although every new library you add is downloaded once.

Accounts and habits

  • A Google account helps for Android Studio sign-in, Gemini features, and later the Play Console.
  • A GitHub account (free) lets you publish each mini project as a portfolio piece.
  • Keep one folder for the course, for example techbase-android, and one sub-folder per lesson.
  • Study in short regular blocks. Thirty focused minutes a day beats one exhausting Saturday.

A tiny self-check you can do on any computer

Open a terminal (Command Prompt, PowerShell, Terminal or a Linux shell) and run:

bash
# Shows how many CPU cores and what OS you have (Linux)
nproc
uname -a

# Shows free disk space in a readable form (macOS and Linux)
df -h

# Windows (PowerShell): free space on drive C
Get-PSDrive C

You are not looking for a pass mark. You are just learning how much room you have. Write down your RAM and free disk space; you will compare them with the official requirements in the next lesson.

🎯 Your Challenge

Exercise 1: Match the layer

Match each statement to the right layer of Android (Linux kernel, Hardware Abstraction Layer, ART, Framework, App).

  1. "I draw the birthday card the user sees."
  2. "I give every camera, from every manufacturer, one standard interface."
  3. "I provide Activity and notification APIs to developers."
  4. "I control memory and process isolation, so apps cannot read each other's files."
  5. "I run the compiled DEX code on the device."
  1. App. Your own code builds the UI.
  2. Hardware Abstraction Layer. It hides hardware differences.
  3. Framework. It is the set of APIs you call from Kotlin.
  4. Linux kernel. It enforces process and memory separation and security.
  5. ART. It is the Android Runtime.

Self-check: If you matched at least four correctly, you understand the shape of the stack well enough for the rest of the course.

🎯 Your Challenge

Exercise 2: Read the manifest

Look at this manifest fragment and answer the three questions below it.

xml
<application android:label="Market Prices">
    <activity android:name=".PricesActivity" android:exported="true">
        <intent-filter>
            <action android:name="android.intent.action.MAIN" />
            <category android:name="android.intent.category.LAUNCHER" />
        </intent-filter>
    </activity>
    <activity android:name=".SettingsActivity" android:exported="false" />
</application>
  1. What name will users see under the icon?
  2. Which screen opens when the user taps the icon?
  3. Can another app open SettingsActivity directly? (Hint: look at exported.)
  1. Market Prices. The android:label on application.
  2. PricesActivity. It is the only activity with the MAIN action and LAUNCHER category.
  3. No. android:exported="false" means it is private to this app. It is for internal use only, such as a settings screen reached from PricesActivity.
🎯 Your Challenge

Exercise 3: APK or AAB?

Decide for each situation whether you need an APK or an AAB.

  1. You want to email a test build to a friend with an Android phone so they can install it.
  2. You are uploading your finished app to the Google Play Console.
  3. You are running the app from Android Studio onto your own phone through a USB cable.
  1. APK. It is the directly installable file (your friend may need to allow installs from that source).
  2. AAB. Google Play requires bundles for new apps, and uses them to create optimised APKs for each device.
  3. APK. Android Studio builds and installs a debug APK for you behind the scenes.

Phase 10 of 11
Common Beginner Mistakes (and How to Fix Them)

These are not code errors yet, but they are the mistakes that stop beginners in their first week.

Mistake #1: Trying to learn everything before starting. The problem: reading about Android for weeks and never installing anything. The fix: follow the lessons in order and type each example. Understanding grows from doing.

Mistake #2: Confusing Android with Android Studio. The problem: Android is the operating system on the phone; Android Studio is the program you use on your computer to build apps. The fix: remember "Studio is the workshop, Android is the road the finished vehicle drives on."

Mistake #3: Confusing Kotlin with Java and thinking you must learn Java first. The problem: old tutorials insist on Java. The fix: you do not need Java first. Kotlin is Google's preferred language and this course teaches it from zero. Kotlin can use Java libraries, so nothing is wasted if you read Java later.

Mistake #4: Copying code you do not understand. The problem: it works until the day it breaks, and then you cannot fix it. The fix: after each snippet, say in your own words what each line does. If you cannot, re-read the explanation before moving on.

Mistake #5: Using a very old tutorial. The problem: Android changes quickly. Screens built with XML layouts, findViewById and the old kapt tool still exist in many blog posts, but modern projects use Compose, version catalogs and KSP. The fix: check the date. If it is more than a couple of years old, prefer the official documentation or this course.

Mistake #6: Downloading Android Studio from a random website. The problem: unofficial copies can contain malware or be badly out of date. The fix: download only from developer.android.com/studio, and compare the checksum if you want to be extra careful (lesson 02 shows how).

Mistake #7: Expecting the emulator to be fast on any machine. The problem: with low RAM or no virtualisation support, the emulator can crawl. The fix: use a real phone (lesson 05) or lighter emulator settings (lesson 04).

Phase 11 of 11
Knowledge Check

Answer each question in your head or on paper, then reveal the answer.

Question 1. Who leads the development of Android, and what is AOSP?

Google leads Android. AOSP, the Android Open Source Project, is the open-source core of the operating system that manufacturers build on to create their own versions.

Question 2. What is the difference between an APK and an AAB?

An APK is an installable package. An AAB (Android App Bundle) is the publishing format you upload to Google Play, which uses it to generate optimised APKs for each device configuration, giving smaller downloads.

Question 3. What does ART do?

ART, the Android Runtime, runs your app's compiled (DEX) code on the device. Your Kotlin source is compiled on your computer, packaged into the app, and ART executes it on the phone.

Question 4. Which two things in AndroidManifest.xml make an activity the one that opens when the user taps the app icon?

An intent-filter containing the action android.intent.action.MAIN and the category android.intent.category.LAUNCHER.

Question 5. Name the six official programmes this course follows.

Android Basics with Compose (ABC), Jetpack Compose for Android developers (JC), the Modern Android App Architecture pathway (ARCH), the Make your Android app accessible pathway (ACC), the Basics of Kotlin Multiplatform pathway (KMP), and the Google Play Store Listing Certificate (PLAY).

Open your finished project in Android Studio. Check that the .gitignore file the wizard created is in the project root. It keeps local.properties, build folders and keystores out of Git. Never commit passwords or signing keys.

2

Choose Git > Create Git Repository… (or VCS > Enable Version Control Integration in older versions), select the project folder, then open Git > Commit, tick every file, and write the message “Add Android lesson 01 project”.

3

On github.com click New repository, name it android-lesson-01-welcome-to-android-development-what-androi, set it to Public, leave Add a README unticked, and click Create repository.

4

Back in Android Studio choose Git > Manage Remotes…, add the repository URL as origin, then choose Git > Push… and push your main branch. Prefer the terminal? Run git remote add origin <your-url> then git push -u origin main.

5

Add a README.md with a screenshot of your app running and a short description. Employers and clients read READMEs first. Your project is now part of your public portfolio. 🎉
